# AI Assistant Workflow for Commits & Pushes

## When User Asks to Commit and Push

### Step 1: Check Current State
```bash
git status
git branch  # Check current branch
```

### Step 2: Pull Latest Changes First (CRITICAL)
```bash
# Always pull before pushing to avoid conflicts
git checkout dev
git pull origin dev

# If on feature branch, update it with latest dev
git checkout <feature-branch>  # if applicable
git merge dev  # or rebase if preferred
```

### Step 3: Stage Changes
```bash
git add .
# Or selectively: git add <specific-files>
```

### Step 4: Commit with Descriptive Message
```bash
# Use clear, descriptive commit messages
git commit -m "Brief description of changes"
# Examples:
# - "Add user authentication endpoint"
# - "Fix login form validation"
# - "Update API response format"
```

### Step 5: Push to Current Branch
```bash
# Push to the branch you're on
git push origin $(git branch --show-current)

# If first push, set upstream:
git push -u origin $(git branch --show-current)
```

### Step 6: Verify Success
```bash
git status  # Should show "Your branch is up to date"
```

## Important Rules

1. **NEVER push without pulling first** - Always sync with remote
2. **NEVER commit directly to `dev` or `main`** - Use feature branches
3. **If conflicts occur** - Resolve them before pushing
4. **If on wrong branch** - Ask user or switch to appropriate branch
5. **If uncommitted changes exist** - Handle them (commit, stash, or discard)

## Quick Workflow Script

When user says "commit and push", execute:
```bash
# 1. Check status
git status

# 2. Pull latest
git checkout dev
git pull origin dev

# 3. Return to working branch (if not on dev)
CURRENT_BRANCH=$(git branch --show-current)
if [ "$CURRENT_BRANCH" != "dev" ]; then
    git checkout $CURRENT_BRANCH
    git merge dev  # Update feature branch
fi

# 4. Stage and commit
git add .
git commit -m "Update: [describe changes]"

# 5. Push
git push origin $CURRENT_BRANCH
```

## Conflict Handling

If merge conflicts occur:
1. Show user which files have conflicts: `git status`
2. Let user know conflicts need manual resolution
3. After resolution: `git add . && git commit -m "Resolve merge conflicts"`

## Branch Management

- If user is on `dev` or `main`: Warn them or create feature branch
- If no branch exists: Create one with `git checkout -b feature/description`
- After push: Confirm branch name and suggest next steps (PR, merge, etc.)
